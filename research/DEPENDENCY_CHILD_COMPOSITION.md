# Invented producer composition in the bound child

2026-10-19. Evidence: **static-inference**, **offline-tested**. Native English
and native Wi-Fi FTP remain first; FL2/FL3 is deferred.

This extends the [source-only child preflight](DEPENDENCY_CHILD_PREFLIGHT.md)
through the complete prospective producer. Its only exposed composition mode
accepts an explicitly invented packet. The ordinary CLI still refuses actual
activation. No installed dependency or protected-input observation is performed.

The parent freezes an ordinary source/runtime request plus independent policy,
package and root digest expectations, and a whole-file packet digest. These are
caller declarations established before launch, not authenticated authorization.
The packet contains invented package metadata, cached inert Python programs,
invented read receipts, root observations and byte strings. No packet path is
used as an installed-file read target: the invented reader is a closed dictionary.
The fake cipher returns published known-answer values; it performs no encryption.

The standalone bootstrap checks four exact authored source buffers (entry, pure
contract, producer and invented operations), the bounded packet's complete receipt,
and the isolated runtime before executing any authored entry. Authored modules
execute from those buffers in an empty `tools` namespace. Their whole-file hashes
also supply the producer's source identity roster; caller-supplied inert identity
placeholders cannot replace the actual buffers in this composition.

The producer installs its real Python audit hook and requires nonce acknowledgement
before the invented bootstrap. Five fake loader calls emit manual `sys.audit`
events without calling an OS loader. The real source hook runs eleven invented
modules. The producer writes its expectation, binding, journal, transcript, audit
acknowledgement and result into a new exclusive subdirectory. It verifies durable
raw publication before one callback; two public-vector lookup passes comprise
48 simulated cipher calls. Cleanup releases owned source aliases, finder, wrapper
and invented helpers, preserving foreign replacements and the first failure.
Permanent audit hooks are made inert before the disposable child exits.

Before reporting success, the child validates the newly saved record contract.
The parent separately rereads the packet and all four authored sources, checks
their original receipts, and recomputes the pure contract from the six saved
artifacts. Trace starts/completions must be nested, and completion order must
match journal `python_import` events. Saved expectation/binding, invented flags,
audit acknowledgement and exact result shape must agree. Fresh whole-file hashes
must match the child-reported artifact roster. Merely printing a success object
does not satisfy this composition.

Process ownership, exclusive attempt creation, bounded waits, single termination
attempt and refusal/completion handling come from the existing child entry.
Timeout/interruption cannot pass and never cause an automatic relaunch. Output
acceptance limits are not disk quotas or a hostile-code sandbox. Reviewed authored
source and invented cached source remain trusted execution inputs. Interpreter,
standard-library and parent execution are not binary-authenticated by this design.

Every accepted result retains `test_injection_used: true`, false installed/actual
observation, false operational acceptance/authorization and false feature,
recovery and device-write flags. Existing historical records and seventeen saved
retrospective blockers are unchanged. A new synthetic pass cannot repair historical
approval or qualify installed cryptography, transitive native libraries, firmware
decoding, English, FTP or rollback.
