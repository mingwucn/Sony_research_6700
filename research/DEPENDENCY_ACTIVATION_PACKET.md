## Exact candidate and missing bindings

invented qualification and new collector qualification, source-review records,
the exact refusing CLI check, intended read/execute/write categories, and the
fixed public ECB/CBC vector plan. Historical launcher and runtime observations
are separately labeled historical/qualification metadata. They do not supply
independently current installed-package, root, source-cache or runtime evidence.
No missing expected digest/path/command is invented or installed as target support.

The minimum coherent actual successor still needs:

1. A separate closed noninjected request, exact-buffer child branch and result

2. Complete package freshness collection before trusted/native dependency
   bootstrap, linked to independently pinned manifest/RECORD metadata and an
   explicit freshness policy. Current data and historical receipts cannot be
   relabeled as fresh.
3. Explicit prospective config/cache preparation from separately approved source
   observations. Preserve original-file and canonical-object digest domains.
   Eleven exact cached Python sources must agree with fresh installed bytes.
4. Exact isolated runtime/profile/optimization checks, module-resolution and
   preloaded-module rules, reviewed scope and applicable owner authorization.
5. An actual-record parent verifier with a fixed artifact roster, binding checks
   and refusal tests. Ordinary parent imports remain a declared trust boundary
   unless an independently frozen executing-parent contract is added.
6. One exclusive attempt, bounded launch/wait/termination/reap and explicit
   reconciliation on uncertain completion. No automatic retry or protected
   callback; only the fixed public-vector computation is contemplated.

The current dependency profile requires eleven Python modules and five native

public-vector operations precede guard completion; complete-before-any-cipher-use
is not a property of this producer.

## Implemented collector, qualified only with invented data

`tools/dependency_package_preflight.py` now prepares the missing complete
freshness stage. It validates the existing expectation/package/config/cache/source
bindings before observing anything, enforces the concrete reader's eight-MiB
per-file bound, and compares each of 351 fresh package reads with independently
supplied manifest hashes/sizes and prior cross-API identities. It checks five
trusted origins, compares all eleven fresh Python source buffers to the pinned
cache, and checks root identities before and after collection. No dependency
bootstrap, loader, cipher, process or file-output step is called.

The collector retains every absolute opened receipt. A separate deterministic
projection changes only `path` to the manifest-relative key, recording both
receipt hashes. The fresh relative receipts form a newly recomputed package
proof; prior and observed package hashes remain distinct. All observer receipts
are detached before the next callback. Package/trusted file contents are discarded
after validation, not included in returned metadata.

Its API is an invented qualification seam, not a security sandbox: arbitrary
Python callers can bypass a private function or supply forwarding substitutes.
The exposed seam refuses `RuntimeOps` and subclasses; ordinary CLI exits 2.
An actual successor must integrate and bind the collector before dependency
bootstrap, record partial outcomes and preserve stop/reconciliation rules.
The current collector is not integrated into an actual child route.

This is a bounded collection pass on a cooperative filesystem, not an atomic
snapshot: a file may change after its individual read. Root checks do not prove
immutability of all children. Before actual execution, the exact entry must
define/recheck the source/native/trusted freshness interval and retain this limit.
No current installation, native cryptography, firmware, English, FTP, recovery or
device-write gate is established by invented collection or a prepared packet.
