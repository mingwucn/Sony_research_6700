## Purpose and current boundary

The [retrospective comparison](DEPENDENCY_DIGEST_DOMAINS.md) retained seventeen
blockers. Historical records cannot acquire missing guard, durability or cleanup
events through translation. `tools/dependency_producer.py` instead performs the
operations that would produce the successor record grammar, qualified here with
invented sources, receipts and native-loader/cipher substitutes.

The ordinary CLI always returns `needs_review`, `real_activation_pending`, exit 2.
`produce_invented` marks test injection and refuses `RuntimeOps` instances and
subclasses. This Python API is a qualification seam, not a security boundary:
Python callers can invoke internal functions or supply forwarding substitutes.
No caller declaration authorizes a real dependency run. `RuntimeOps` is future,
unactivated observer code; it has not been qualified against an installation.
There is no firmware, GDT, device or arbitrary protected-continuation API.

## What the engine does

The caller supplies a typed expectation, installed-package record, review-binding
declaration, exact configuration/cache text and authored-source identity buffers.
The package and expectation pass the unchanged pure contract before output
reservation or dependency execution. Hashes cover the original supplied UTF-8
configuration/cache bytes; they are not hashes of a second canonicalization.
Caller-supplied producer identity buffers are hashed but do not authenticate the
Python code currently executing. Review hashes are declarations, not approval.

All eleven cached source texts must match expected hashes, sizes and concrete
module paths before any is executed. The five native-library paths and five
trusted origins are explicit. Root identities have a separate directory/ancestor
observation domain. The concrete file reader bounds reads, rejects links/reparse
points, correlates descriptor/path stamps and hashes, and checks ancestor
identities. These cooperative filesystem checks are not a hostile-filesystem
sandbox or proof of OS-mapped native bytes.

During imports the engine correlates fresh reads with the exact executing source
buffer and records completed imports only after execution and ownership checks.
Partial source failures remain sticky. Supplemental intent/completion traces
are returned separately; the unchanged pure contract checks completed imports,
not source-execution bracket semantics or their durability. Unavailable optional
backend probes stop meta-path traversal; reachable fallback candidates refuse.

The native wrapper permits one pending intent, one matching audit event and a
post-return receipt. Extra, duplicate, mismatched, reentrant or late requests
refuse. Guard failures remain sticky when callers catch exceptions. The public
six-vector plan covers default/generic ECB/CBC requests at three key sizes:
twelve cases, twenty-four comparisons per vector pass. Tests use a lookup table,
not installed cryptography, and native loader calls are simulated.

The raw transcript ends at `guard_finished`. Exclusive output files journal
write, flush, fsync, close and fresh-read verification individually, then claim a
single fixed public-vector callback. A second raw verification precedes the
claim. A failed step prevents subsequent success markers/callback entry. An
uncertain close relinquishes its handle and is not retried. No atomic publication
or crash-durable directory-entry guarantee is claimed.

Cleanup disables the retained audit hook, releases owned wrapper/finder/aliases
individually, preserves foreign replacements and the primary failure, and attempts
output close even if another cleanup action fails. Python audit hooks cannot be
removed. Inert delivery after cleanup is qualified in a disposable child using
manual audit events, with no actual native load or shell execution.

After cleanup and journal close, the engine reads its new journal and applies
the unchanged pure record contract. A successful result means consistency of
invented records and the exercised instrumentation. All operational, execution,
feature, recovery and device-write claims stay false. Transitive OS dependencies,
native mapped-image identity and actual cipher correctness remain unattested.
Failed attempts retain partial exclusive outputs without a success result; they
require inspection, not automatic replay into the same destination.
