## Findings, failure handling and review

The initial failure was a lab configuration error: upstream SIZE requires the
authorizer's `l` metadata permission. Static source confirmed this; the peer now
uses `elrwf` while its command allowlist still excludes listing/deletion. The
failed queue/spool/log were preserved; its lease closed and process exited.
Every later run used a NEW workspace after inspecting the previous outcome.
No failed upload was blindly retried.

Stock-style STOR with upstream `wb` overwrote/truncated a synthetic temporary.
The custom peer therefore advertises LAB-NOCLOBBER-V1, uses exclusive creation,
and finalizes via exclusive hard-link then unlink. A destination created after
RNFR is preserved. That extension is not generic FTP atomic rename semantics.
Only its exact authenticated missing token establishes absence; present files
require full bounded RETR SHA-256 plus size, including after finalization.

Independent static review found receive-bound, shutdown-error, logger-propagation,
in-flight rename, abandoned pending-STOR and startup-cleanup edges; these were
corrected. Review then found that deferred TLS shutdown could release a marker
before its upload file closed, despite the earlier 18 passing tests. The peer
now tracks actual handles and keeps open uploads guarded. The added nineteenth
case forces data shutdown to defer, confirms the file remains open, and proves
a second session cannot finalize it. Acceptance was not weakened after failure.

The final cases include 100 files/50 groups, source preservation, queue reload,
hash-versus-size collision, exclusive upload/finalization races, TLS/name/trust/
authentication refusals, protected passive binary transfers, clear-data/active
mode rejection, receiver limits, injected permission/quota/partial disconnects,
lost upload/rename completion, interrupted link/unlink and listener cleanup.
Read-only reconciliation makes no repeat upload/rename or destructive cleanup.
