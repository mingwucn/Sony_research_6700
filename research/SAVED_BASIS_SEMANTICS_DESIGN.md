# Saved-basis semantic validation design

Evidence: **static-inference**, **offline-tested**. This package extends the
[existing complete binding-plan comparison and nine-role preflight](sessions/20261019-RA-003-binding-basis-diagnostic.md).
It checks what the saved fields must mean together before a later bounded
metadata diagnostic. It does not establish that the historical observations
occurred, authenticate their raw inputs or authorize another observation.

English and native camera-to-server Wi-Fi FTP remain primary. Shared exact-source
preparation supports their later analysis; no English resource or FTP backend
mapping is established by this validator. FL2/FL3 remains deferred.

The candidate is an authored pure validator in the ignored private workspace,
with forty pinned authored helper/fixture/producer sources. No firmware, camera
dump, raw prefix, source-cache body, operational constants or native payload is
needed for this qualification. Complete invented envelopes follow the production
producer schemas; incomplete historical test fixtures are explicitly refused.

| Saved role | Schema, arithmetic and correlation checks |
|---|---|
| Stream summary | Complete key set, typed flags/limits, hash shapes, fixed test counts, finite timings, feasible aggregate counters, declared span bounds and non-overlap |
| Component-prefix summary | Complete key set, declared spans tied to stream metadata, classification vocabulary and bounded observation fields |
| Measured output | Complete envelope, cross-hashes/counters, package chunk arithmetic, unique FDAT length, complete decoded-header fields and span lists |
| Tar directory | Complete member/link fields, exact extent, aligned ordered offsets, canonical unique member names, opaque links, end markers/counts and encoded metadata size |
| Selection | Five ordered unique indices, exact directory member correspondence, regular positive-size members |
| Member-prefix identification | Existing complete row checks plus equality of full-member prefix and payload hashes when the member is at most 4096 bytes |
| Accepted inventory | Existing directory/member/expanded-row equality and ordered candidates; original component-prefix identification newly bound in full |
| Lead plan | Existing exact pure derivation and ordered lead correspondence, without calling a planner |
| EXT observation | Existing field-width/schema checks plus derived features, effective fields, geometry, statuses and ordered issues/blockers; explicit branches for empty raw dictionaries |

EXT arithmetic is factored from the pinned authored observer after its raw-field
reads. Saved validation supplies scalar fields directly; it does not synthesize a
raw prefix and call an observer. Tests compare the factored arithmetic with the
original observer on invented bytes and include an independent simple geometry
calculation. Shared arithmetic is not independent reproduction.

Aggregate stream counters establish only that some payload sequence is possible.
Each directory extension gap must admit a feasible count of extensions, at
1024 through 66048 bytes each. The total count must fit the sum of those per-gap
ranges. Headers and nonempty padded payloads are accounted for. Neither reconstructs the historical
sequence or verifies extension contents. Saved hash equality is consistency,
not an independent hash of the raw input.

The caller must authenticate the pure preflight module. Its bounded detached
clone precedes semantic traversal and incremental JSON fingerprinting, with an
8 MiB encoded bound. No path, source buffer, read callback, parser facade or
operational entry is accepted by the candidate API. This is not a sandbox or
whole-process memory cap.

Remaining prerequisites include source/helper authority binding, a separately
frozen and independently reviewed actual saved-record diagnostic, historical
event receipts, raw hash/classification/padding truth, fresh observation scope and
rights, and the retained dependency/native-policy and operational-seal blockers.
`complete_saved_basis_semantic_revalidation` remains false. No feature support,
execution, recovery or device-write gate follows from this design.
