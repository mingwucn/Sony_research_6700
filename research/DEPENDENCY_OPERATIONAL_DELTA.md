## Finding that determines the next implementation

The frozen prospective entry calls the old `run_gdt_with_runtime` wiring, which
calls `runtime.run_dependency_then_protected`. Its parent expects
`dependency_probe_raw_result_v1` and the previous dependency journal events.
The new collected dependency engine publishes a different transcript, collection,
proof transition, audit acknowledgement and completion contract. Its runtime
route constructs its own `RuntimeOps`; that observer's callback only runs public
vectors. It cannot currently invoke the protected controller continuation.

The new controller bridge exposes `run_invented` only and explicitly refuses
`RuntimeOps`. Switching its call to `produce_collected_runtime`, or merely
removing that refusal, would not supply a working continuation. Injecting a
custom runtime observer or monkey-patching `RuntimeOps.callback` would bypass
the current runtime route's no-custom-observer contract. Neither is an accepted
migration. No source or runtime guard was changed in this package.

## Residual limits and later device gates

Sequential collection and loader-adjacent descriptor reads do not prove an atomic
mapped image. Parent/interpreter/stdlib/OS-loader trust, transitive DLLs, effective
loader flags and per-case acceleration selection remain limited as previously
recorded. The initial vector use precedes final guard completion;
`complete_before_any_cipher_use` remains false. These are limits on claims, not
a newly invented requirement to authenticate the entire operating system before
any narrow observation. The exact act review must state its accepted trust
boundary without silently clearing historical blockers.

No current result proves mainland body/build correspondence, English resources
or restriction consumers, a native FTP backend/media/network lifecycle, rollback,
or protected-state coverage. Owner-required recovery before firmware writes still
needs exact-body evidence, independently verified copies where possible and a
conditional recovery procedure. Those later device gates cannot be passed by
host source review. This package requests and performs no device step.

The frozen metadata scope remains unchanged: two leads, nine metadata roles,
five complete historical blocks, separate two-phase lineage, at most 32,768
descriptor bytes per lead / 65,536 total, no inode/bitmap/directory/content reads.
Any future change of input scope or acceptance threshold requires explicit
documentation and review; the present delta adds no read authority.
