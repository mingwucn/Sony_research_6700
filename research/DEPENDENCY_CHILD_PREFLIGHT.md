## Execution boundary

`tools/dependency_child_entry.py` freezes three authored sources: this entry,
the unchanged pure dependency contract and the prospective producer. A separate
ordinary runtime-metadata observation supplies expectations before the target
child starts. Source receipts include whole-file size/hash and correlated
descriptor/path identities; directory/ancestor observations are separate.
The review digest is a caller declaration, not consent or independent review.

The parent reserves a new attempt directory and writes the exact request and
started record before one isolated `-I -S -B -X utf8 -c` invocation. A standalone
standard-library bootstrap reads the request and all three source buffers,
checks their complete receipts, concrete role paths and ancestor identities,
and compares the exact runtime profile before executing any authored entry.
The profile includes executable/prefix strings, complete version text, cache
tag, path list, machine word-size limit and startup flags; optimization is zero.

The bootstrap compiles the verified entry buffer with `dont_inherit=True` and
`optimize=0`. The entry correlates the bootstrap text with `sys.orig_argv`, then
executes the exact verified core/producer buffers in a new empty `tools`
namespace. It does not import the repository package initializer or resolve
these authored modules through a working-tree import path. Interpreter, standard
library and OS startup remain trusted; their binary/file closure is not attested.
The exact runtime profile is an observation, not interpreter authentication.

The loaded producer's audit wrapper is installed and receives a fresh nonce
probe. An acknowledgement must occur once before any dependency bootstrap.
The hook is disabled and an inert manual event is delivered after cleanup.
No `RuntimeOps.bootstrap`, installed module, source cache, native library or
cipher is invoked. The parent validates a closed result including the exact
runtime, source/request hashes, acknowledgement and false authority flags.
Duplicate keys, malformed/deep/oversized output, extra fields and promoted
claims refuse and retain a completion record.

## Producer integration and process outcomes

The producer itself now requires nonce acknowledgement immediately after hook
installation and before trusted dependency bootstrap. Missing, wrong or replayed
probes refuse, including when an existing Python hook suppresses a new hook's
installation. Its ordinary CLI still refuses; invented operations remain labeled.
The acknowledgement is recorded in a separate exclusive receipt, preserving
the unchanged core event grammar. The producer's executing-source identity
claims remain caller supplied; the child preflight does not invoke that producer.

One parent process owns a single child. A normal wait is bounded to at most
30 seconds. On timeout or interruption after launch, the parent attempts one
host-child termination and one bounded cleanup wait; it never respawns. Failure
to establish termination retains `needs_process_reconciliation`, PID and partial
outputs. A timed-out or interrupted run cannot become accepted even if it later
returns zero. An existing attempt directory is not overwritten or replayed.

Output acceptance reads are limited to 65,536 bytes per file; this is not a
disk-output quota or hostile-code sandbox. Source code is reviewed authored
input, not arbitrary untrusted execution. Exclusive creation, fsync and stat
correlation do not establish atomic/crash-durable directory publication or
resistance to a hostile filesystem. Uncertain existing results need inspection.
